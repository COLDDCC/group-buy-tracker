# 代购团购收集助手（Chrome / Edge 插件）

Edge 内核也是 Chromium，用的是和 Chrome 一样的插件格式（Manifest V3），下面这套文件两边都能直接用，
不用改代码，装的时候看「安装」那节里对应浏览器的步骤就行。

在菌核屋商品页点一下插件图标，自动抓取**商品图片链接、名称、价格**，写进飞书**电子表格**（包括嵌在知识库/Wiki
里的那种）；**团员名字这一列插件不填**，留给你在表格里手动核对、填写（同一件商品可能被好几个人下单）。

## 它做了什么

- 打开商品页 → 点插件图标，弹窗一打开就会自动抓一次图片、名称、当前价格，不用再手动点一下。
  如果商品图片是页面加载完一会儿才出来的（懒加载），弹窗里有个「重新抓取」按钮，等图片显示出来后
  再点一下补抓。
- 图片那一格写的是飞书的 `=IMAGE("链接")` 公式，飞书会自己联网把图片下载渲染成缩略图——插件不用
  下载图片，也不需要额外权限。**保存后图片不会立刻显示**，飞书要花几秒到十几秒去加载，格子会先
  短暂显示 `#ERROR` 或者空白，等一下就好，不是保存失败。
  已知 `=IMAGE()` 不认 `.webp` 格式的图片，会一直显示 `#VALUE!`。菌核屋（suruga-ya.jp）的图片链接
  刚好经常是 webp 版本，插件会自动把它换成同一张图的 jpg 版本再写进去；别的网站如果给的也是 webp
  链接，插件目前没法自动处理，图片那格会显示不出来，但不影响其他字段照常保存。
- 插件会看**今天是不是周六/周日**（或你在设置里加的法定节假日），自动把抓到的价格填进「平时价」
  还是「周末价」那一栏；抓到的划线原价（如果页面上有）会顺手填进另一栏，供你核对。
- 所有字段在保存前都能手动修改——抓取只是省去打字，不保证 100% 准确，尤其是价格识别依赖页面结构，
  第一次用建议核对一下。
- 点「保存到表格」：插件会按「商品链接」这一列去查表格里有没有这一行，有的话**只更新价格等字段**
  （不会新建重复行，也不会把已经填好的团员名字覆盖掉，因为团员那一列插件从来不写）；没有的话才新建一行。
  链接里常见的追踪参数（utm_*、spm、_t 之类）会先被插件去掉再比对，避免同一件商品因为每次打开链接
  末尾的追踪参数不一样，被误判成不同商品、重复建行。

## 安装

先把这个仓库下载/克隆到电脑上，解压后拿到一个文件夹（里面能直接看到 `manifest.json`）。然后按你用
的浏览器选一种：

**Chrome：**
1. 地址栏输入 `chrome://extensions`，右上角打开「开发者模式」。
2. 点「加载已解压的扩展程序」，选中上面那个文件夹。

**Edge：**
1. 地址栏输入 `edge://extensions`，左下角（或左侧菜单）打开「开发人员模式」。
2. 点「加载解压缩的扩展」，选中上面那个文件夹。

两边装完插件栏都会出现图标，建议固定住方便点击。两个浏览器可以各装一份，配置（App ID/Secret、
表格链接等）要分别填一次，因为每个浏览器的插件存储是各自独立的，不会互通。

## 准备飞书电子表格

1. 表格想怎么建都行，列名、列的顺序插件都不看——它只认你在设置里给每个字段指定的列字母。
   如果还没想好要哪些列，可以先抄一份类似这样的表头（照抄或自己删改都行）：
   `名称 | 图片 | 链接 | 平时价格 | 实际价格 | cn | 个数 | QQ号`。其中「cn / 个数 / QQ号」这类插件
   根本不知道的列，只要不在插件设置里给它们配对应字段，插件就永远不会碰，放哪都行。
2. 打开你要写数据的那个分表标签页，把浏览器地址栏的完整链接复制下来，等下要填到插件设置里。
   链接大概长这样（两种都支持）：
   - 嵌在知识库里：`https://xxx.feishu.cn/wiki/UkmCweIaJiwuSxxxxxxx?sheet=eACgUf`
   - 独立电子表格：`https://xxx.feishu.cn/sheets/shtXXXXXXXX?sheet=xxxxx`
   一定要确认链接里带着 `?sheet=` 这一段（对应你正在看的那个分表标签页），不是文档首页的链接。

## 创建飞书自建应用（用来调 API 写数据）

1. 打开 [飞书开放平台](https://open.feishu.cn/app)，创建一个「企业自建应用」。
2. 在应用的「权限管理」里开通电子表格相关权限（搜索 sheets / 电子表格，把读写行、读表格信息相关权限都
   勾上；如果表格是嵌在知识库里的，再搜索 wiki，把「获取知识库节点信息」权限也勾上，插件需要它把
   Wiki 链接解析成真正的表格）。
3. 发布这个应用版本（企业自建应用一般需要管理员在后台审核通过一次）。
4. 回到你的表格，右上角「协作者」/分享里，把这个应用添加为协作者（否则应用有权限也进不了这份表格）。
5. 在应用详情页找到 **App ID** 和 **App Secret**，填到插件设置里（这两项只存在本机浏览器里，不会
   跟着 Chrome 账号同步出去）。

## 配置插件

右键插件图标 →「选项」（或点插件弹窗右上角的 ⚙）：

1. 填 App ID / App Secret。
2. 把第一步复制的表格链接粘进「表格链接」框。
3. 给 5 个字段分别填上它们在表格里对应的列字母（默认 A/B/C/D/E，对应名称/图片/链接/平时价/周末价，
   跟你表格实际布局对不上就改）；哪个字段不想让插件写，把那一格清空即可。「商品链接列」是必填的，
   插件靠它判断是不是同一件商品。核对一下「表头行号」（默认第 1 行是表头，数据从第 2 行往下写）。
4. 需要的话，补充法定节假日日期。
5. 点「测试连接」，显示「连接成功，找到分表『xxx』」就说明配置对了——这个「分表名字」要跟你正在看
   的那个标签页名字对得上，对不上说明表格链接复制错了标签页。

## 保存显示成功，但表格里没看到数据

保存成功后弹窗会显示写到了第几行（比如「已写入新记录 ✅（第 2 行）」），照这个去表格里定位，比自己
翻着找准。如果还是找不到，按顺序排查：

1. 确认你正看着的分表标签页，和「测试连接」返回的分表名字是同一个（一份文档里可能有好几个标签页）。
2. 确认「表头行号」跟实际一致——填错了，插件会去不该找的行找数据。
3. 确认「商品链接列」在你开始用插件之前是不是已经有别的内容（哪怕是模板里剩下的），有的话插件会
   认为已经有数据，把新记录接着往后写，可能写到很靠下的地方。
4. 确认 5 个字段设置的列字母，跟表格里"名称/图片/链接/平时价格/实际价格"实际所在的列对得上。

## 已知局限 / 可以继续改进的地方

- `=IMAGE()` 公式不认 webp 格式图片，只有菌核屋这一个站点做了自动转 jpg 的处理，别的网站给的
  webp 图片链接目前只能手动改成 jpg/png 链接。
- 图片会不会显示出来，插件这边判断不了——保存这一步只是把公式文字写进格子，图片是飞书后台自己
  异步加载渲染的，链接失效、被防盗链挡住、格式不支持这些情况插件都不知道，只能你自己肉眼确认。
  格子里报错的话可以按错误类型大致判断原因：`#VALUE!` 通常是图片格式不支持（比如 webp）；
  `#ERROR` 通常是飞书那边根本抓不到这张图（链接失效、图片站有防盗链/反爬限制等），后者没什么
  好办法，只能换一张这个站点能正常访问的图。
- 价格识别是靠页面文字里的 `¥`/`￥`/中文"元"/日文"円"（支持千位逗号，如 1,500円）加数字、以及有
  没有「划线价」样式来猜的，不同商品页排版不一样，猜不准是正常的，保存前记得看一眼再点保存。
- 「周末/节假日」只按你电脑当前日期判断，不会自动同步法定节假日日历，需要的日期要自己加到设置里。
- 查重、找空行都是靠插件读一大段单元格内容再在本地比对，如果同一个分表里已有几千行数据，速度会
  稍微变慢，但不影响正确性。
